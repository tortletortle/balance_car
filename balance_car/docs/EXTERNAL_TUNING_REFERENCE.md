# 外部资料精华笔记（调车版）

## 1. 这份文档是干什么的

这不是单纯的“资料收藏夹”，而是把几份官方手册、应用笔记里真正对当前平衡小车项目有帮助的结论，压缩成一份你能直接拿来调车、复习、答辩的笔记。

重点只保留三类内容：

- 哪些结论能直接指导当前代码结构
- 哪些结论能直接指导直立环调参
- 哪些结论能直接帮助你定位现在这种“零点附近空挡、过门槛突然蹿、左右轮低速不一致”的问题

---

## 2. 先记住这 6 句话

1. `P` 负责把车“顶住”，`D` 负责给它“刹车”，`I` 主要负责修正长期偏差。
2. 加速度计算出来的倾角，只在没有明显线加速度时更可靠；车一动起来，就不能只信加速度计。
3. 陀螺响应快，但有零偏和温漂，所以必须静止校零，而且最好给一点上电稳定时间。
4. 互补滤波的核心思想不是“高级”，而是“低频信加速度计，高频信陀螺”。
5. 低速死区、启动补偿、输出斜坡如果没调对，会伪装成“`P` 太小”或者“姿态环没写好”。
6. 编码器方向、电机方向、控制正负号必须分层维护，不能把所有方向问题都混成一个 `sign` 去硬改。

## 3. 平衡控制 / PID：资料里的精华

### 3.1 资料结论

从 Microchip 的倒立摆 `AN964` 可以提炼出几个最有用的点：

- 比例项增大后，系统会更快地去纠正误差，但过大时会引起更强的振荡趋势。
- 积分项的主要作用是消除长期稳态偏差，而不是负责“把车扶起来”。
- 微分项相当于增加阻尼，用来抑制过冲和来回摆动。
- 调参时不要同时乱动多个参数，而是每次只改一项，看系统现象怎么变。

### 3.2 对当前项目的直接含义

对应到你现在这个项目，可以直接记成下面这句话：

- `KP` 不够：车软、接不住、扶着也没劲
- `KP` 够了但 `KD` 不够：会来回摆、回正后又冲过去
- `KD` 太大：会发紧、发抖、噪声感明显
- `KI` 太早介入：会把零点附近的问题放大，甚至把原本是死区/补偿的问题误认为控制问题

### 3.3 对你当前阶段的调参结论

这部分是**结合资料和你当前代码现状做出的工程推断**：

- 你现在还在整车直立环初期，`KI` 完全可以先保持 `0`
- 先把方向、死区、启动补偿、输出限幅这些“基础物理链路”调通
- 再用 `KP` 找到“能接得住”的范围
- 最后再用 `KD` 把回摆压下去
- 真到后期出现“长期微小偏角总要靠手修正”，再考虑上 `KI`

也就是说，**现阶段不是先调积分，而是先把小车变成一个“方向对、低速区顺、能被 `P` 顶住”的系统**。

## 4. IMU / 姿态估计：资料里的精华

### 4.1 为什么不能只看加速度计角度

NXP 的 `AN3461` 明确给了一个非常重要的前提：

- 用重力分量推算倾角，本质上默认“当前测到的主要是重力”
- 如果车体正在加速、减速、碰撞、抖动，那么加速度计读数里就不只是重力，倾角估算会被污染

对应到平衡小车上，这意味着：

- 车静止时，加速度计角度适合当“慢参考”
- 车快速前后摆动时，加速度计角度会被线加速度干扰
- 所以运行时不能把姿态直接等同于“加速度计角度”

### 4.2 为什么要融合陀螺

陀螺的优点和缺点非常典型：

- 优点：动态响应快，短时间变化看得准
- 缺点：积分后会漂，零偏会累积成角度误差

所以互补滤波这件事，最本质的理解就是：

- 低频、长期参考：靠加速度计纠偏
- 高频、瞬时动态：靠陀螺提供灵敏响应

这正好对应你当前项目里的姿态估计结构。

### 4.3 零点和校准到底意味着什么

资料里跟你现在最相关的不是“复杂六面校准”，而是下面这几个工程事实：

- 传感器焊到板子上以后，安装误差和板级应力会带来额外偏差
- 陀螺零偏会随温度变化
- 上电刚开始的一段时间，器件通常比稳定状态更容易漂
- 所以“静止采样校零”不是形式，而是为了建立当前这块板、这次上电、这个温度下的参考零点

对应到你项目里，`WHOAMI` 检查和静止校零都是有必要的：

- `WHOAMI`：先确认你现在读到的真是 MPU6050，而不是 I2C 线有问题、地址错了、设备没起来
- 校零采样：在静止状态下估计加速度和陀螺的零偏，作为后续姿态估计的起点

### 4.4 DLPF / 带宽对控制手感的影响

MPU6050 的寄存器手册明确说明了低通滤波带宽配置。把这个结论翻译成人话就是：

- 带宽开得太高：噪声更多，`D` 项更容易抖
- 带宽开得太低：角度和角速度更“干净”，但延迟会变大

所以后面如果你出现下面两种情况，要想到 IMU 带宽：

- 一加 `KD` 就特别吵：可能噪声太大
- 明明方向对，但总感觉反应慢半拍：可能滤波太重、延迟太大

## 5. 编码器 / STM32 定时器：资料里的精华

### 5.1 编码器模式的核心

ST 的 `AN4013` 对 STM32 定时器编码器模式的解释很有用，核心可记成：

- 编码器两相信号进入定时器后，定时器可以直接根据相位关系判断方向并计数
- 计数方向和增减，与输入极性、接线方向、A/B 相定义都有关系
- 定时器还可以对输入做数字滤波，降低抖动误计数

### 5.2 对你项目最重要的工程结论

这份资料落到当前代码里，最重要的不是“定时器原理考试题”，而是下面这件事：

**方向要分层处理。**

你当前代码里已经分成了三种方向语义，这样是对的：

- `encoder_hw_direction_a/b`：硬件接线导致的原始编码器方向
- `encoder_speed_sign_a/b`：控制语义里的速度正方向
- `motor_command_sign_a/b`：电机执行链最终的 PWM 正方向

后面调车时，如果发现“编码器速度正负和姿态控制正负不一致”，不要直接去乱翻电机方向，而是先判断问题到底落在哪一层。

### 5.3 为什么采样周期要固定

编码器速度在你这里本质上是“每个固定周期内的增量”。

所以：

- 采样周期一变，速度语义就变了
- 速度环参数也会跟着失真
- 同样的 `delta` 在 `10 ms` 和 `20 ms` 下不是一个含义

这也是为什么调度周期、IMU 报告周期、速度估算周期都要尽量稳定。

## 6. 电机驱动 / TB6612：资料里的精华

### 6.1 TB6612 真正关键的不是“能转”，而是方向语义

TB6612FNG 的资料里最关键的结论有三条：

- `STBY` 必须使能，否则驱动不工作
- `IN1/IN2` 组合决定正转、反转、短刹车和停止
- `PWM` 只是占空比输入，真正的方向语义由方向脚决定

这对当前项目的意义是：

- 电机“方向反了”不一定是控制器错了，也可能只是执行链符号和机械定义相反
- 所以你把 `motor_command_sign_a/b` 抽成 profile 参数是正确架构

### 6.2 为什么低速区一定要单独看

资料本身不会告诉你“你的电机死区就是多少”，但它会告诉你一个事实：

- 驱动器 + 电机 + 减速箱 + 供电 + 轮胎负载，共同决定低速区的真实起转门槛

所以低速区这些量必须实测：

- A 轮正向起转 PWM
- A 轮反向起转 PWM
- B 轮正向起转 PWM
- B 轮反向起转 PWM

如果这 4 个数差很多，而你代码里只给了一个公共补偿，整车就很容易出现：

- 零点附近像有空挡
- 过门槛突然蹿一下
- 左右轮低速不一致
- 车总是有点偏扭

### 6.3 输出斜坡 `ramp_step` 是什么感觉

`ramp_step` 不是控制器增益，它更像执行链上的“输出爬升速度限制”。

- 太小：感觉系统慢半拍，像推力被拖住
- 太大：会更直接，但也更容易显得冲

所以它不是拿来“把车调稳”的第一工具，而是拿来修执行链手感的。

## 7. 这些资料怎么映射到当前代码

### 7.1 IMU 与姿态估计

- `mod_imu`：负责 `WHOAMI`、原始数据读取、静止校零、报告输出
- `ctrl_attitude_estimator`：把加速度倾角和陀螺角速度融合成姿态估计
- `pitch_fused_mdeg`：当前融合后的前后倾角
- `pitch_rate_mdps`：当前俯仰角速度

### 7.2 角度环

- `ctrl_angle_loop`：把“目标角度”和“当前角度”之间的误差变成控制输出
- `kp_q8 / ki_q8 / kd_q8`：角度环参数
- `error_deadband_ddeg`：角度误差死区
- `angle_cmd`：角度环输出，后面送给速度/执行链

### 7.3 速度环与启动补偿

- `ctrl_speed_loop`：把 `angle_cmd` 和编码器反馈组合成最终 PWM 输出
- `motor_deadzone_pwm_fwd/rev`：启动补偿的正反向目标 PWM
- `deadzone_comp_min_cmd`：小到什么程度以下不触发启动补偿
- `speed_enable_closed_loop`：速度环是否真正开闭环

### 7.4 电机执行链

- `mod_motor`：电机 PWM 限幅、方向映射、斜坡输出
- `motor_ramp_step`：每次更新时允许输出改变多少
- `motor_command_sign_a/b`：执行链最终方向

## 8. 对当前这台车最有用的调车顺序

这个顺序不是照搬某一份资料，而是**结合资料结论和你现在项目状态得到的最实用流程**。

### 第 1 步：先保证方向完全正确

先确认 4 件事：

- 倾倒方向和轮子纠正方向是否一致
- 编码器增量正负是否符合你定义的前进方向
- `motor_command_sign_a/b` 是否已经和实际机械方向一致
- `encoder_speed_sign_a/b` 是否和控制语义一致

### 第 2 步：先把低速区调顺

在当前项目里，先看这几个量：

- `error_deadband_ddeg`
- `motor_deadzone_pwm_fwd/rev`
- `deadzone_comp_min_cmd`
- `motor_ramp_step`

因为只要这里不顺，后面你调 `KP` 的手感就会失真。

### 第 3 步：只调 `P`

目标不是直接放手直立，而是先达到：

- 扶着时它能明显接住你
- 小角度倾倒时它会主动给力
- 不是完全软塌塌没反应

### 第 4 步：加 `D`

当 `P` 足够后，如果出现：

- 回摆很大
- 冲过去又拉回来
- 像弹簧一样左右来回摆

这时再加 `D` 去压阻尼。

### 第 5 步：最后才考虑 `I`

如果后面出现：

- 能站，但长期总有一点前倾/后倾偏差
- 必须靠 `TARGET` 才舒服
- 静态零点长期偏一点

再考虑 `I`，而不是一开始就加。

## 9. 对你当前现象的资料化解释

你前面遇到的症状：

- 零点附近轻晃几乎没反应
- 过门槛后突然蹿一下
- 左右轮低速区手感不一致

结合资料和代码，可以把原因拆成：

1. 角度死区把零点附近的小误差直接吃掉
2. 一旦过门槛，启动补偿又直接把输出拉到较大的 PWM
3. 如果 `ramp_step` 太小，会再叠加一层“憋一下才推”的感觉
4. 左右轮真实起转点不一样，会把整车扭成偏拧、偏扭的体感

所以这类现象不应该第一反应就归因于“PID 不行”，而要先检查：

- 低速死区是不是过大
- 启动补偿是不是远高于真实起转值
- 斜坡是不是太慢
- 左右轮起转阈值是不是差太多

## 10. 建议你现在怎么读这些资料

如果你的时间很紧，就按下面顺序读：

1. 先读 `AN964`，只抓住 `P / I / D` 各自做什么、为什么不能一起乱调
2. 再读 `AN3461`，弄懂为什么加速度计角度不能直接当姿态
3. 再看 MPU6050 手册里滤波和器件说明，理解校零、噪声、延迟这些问题
4. 再看 `AN4013`，把编码器方向、极性、滤波和计数方式理顺
5. 最后回到你自己的代码，把变量名和这些概念一一对应起来

## 12. 最后只记一句话

你现在这台车要进入“能调直立环”的状态，核心不是再去堆更多算法，而是把下面这条链先调顺：

`姿态方向正确 -> 低速区没有空挡 -> P 能顶住 -> D 能压摆 -> 最后才谈 I`

如果这条链顺了，后面换电机、换轮子、换参数，你也能自己维护。
