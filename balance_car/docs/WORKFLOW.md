# 当前阶段工作规则

## 1. 当前阶段定义

当前仓库处于“整理阶段”，不是“正式开发阶段”。

整理阶段允许做的事：

- 梳理旧项目结构
- 记录硬件映射和控制主线
- 提炼可继承原则
- 设计新项目的目录、接口和开发规则
- 建立文档与 Git 管理流程

整理阶段暂不做的事：

- 编写正式控制代码
- 迁移旧项目固件实现
- 引入新的功能模块
- 进行正式联调

## 2. 文档优先原则

每完成一块工作，先完成以下动作：

1. 更新理解文档或决策文档
2. 在 `docs/CHANGELOG.md` 中写明变更
3. 再进行 Git 提交

禁止只改内容不留记录。

## 3. 提交原则

每次提交应满足：

- 范围单一
- 目的清晰
- 能用一句话说明
- 不夹带无关文件

推荐提交粒度：

- `docs: 整理 balance_v3 结构理解`
- `docs: 记录硬件映射与协议结论`
- `docs: 建立重构阶段工作规则`

## 4. GitHub 提交说明

当前仓库已经在 Git 中，但尚未配置远端。

因此当前流程分为两步：

- 第一步：先做本地 Git 提交，形成可回滚历史
- 第二步：待远端配置完成后，再执行 push 到 GitHub

在远端未配置前，不声称“已提交 GitHub”，只记录为“已本地提交，待推送”。

## 5. 当前阶段建议工作序列

建议保持以下顺序：

1. 参考资产整理
2. 硬件资源映射确认
3. 新项目模块边界定义
4. 串口协议与观测接口定义
5. 安全状态机定义
6. 控制环职责拆分设计
7. 通过后再进入正式开发

## 6. 变更记录要求

每条变更记录至少包含：

- 做了什么
- 为什么做
- 是否进入正式开发
- 下一步是什么

## 7. 当前阶段的底线

- 不急于写代码
- 不复制大文件旧实现
- 不把“能跑”误当成“可维护”
- 不跳过文档直接推进
